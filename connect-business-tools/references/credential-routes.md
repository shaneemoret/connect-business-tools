# Use the owner's existing credential manager

Discover custody from installed tools and startup records, not the owner's generic word "credential manager". The common contract is an existing executable prefix that accepts a child command and injects a secret into an environment variable for that child only. The connection profile stores this prefix, the variable NAME and a nonsecret reference, never the secret.

- **Warden:** use its documented registry/map and `warden run ENTRY -- CHILD`. Use the local secure paste form or `add` through a trusted secure channel for storage. Discover its actual path. Preserve expiry/test/purpose metadata on updates. A saved receipt alone does not prove API authentication.
- **1Password or another manager with CLI injection:** use an already authorized service-account/session route, supported secret references and command injection. Consult current official CLI docs. Unlock/authenticate through the manager. Do not print a field with `read`/`get`, export the vault, or put tokens in shell arguments. If injection requires an adapter, author it locally and verify it; do not pretend Warden exists.
- **Bitwarden, OS Keychain, enterprise vault or a password UI without command injection:** inspect the documented local bridge. If absent, explain that stored credentials are not yet usable by agents, and build/install a narrowly scoped owner-approved bridge. Do not request a master password in chat or install a second manager silently. CLI session unlock/refresh must remain under the manager's supported custody.
- **OAuth/per-system gateway:** the gateway owns refresh/locking. Use its command route if it can supply the probe's required token, or author a gateway-native probe/runner. Do not replace it with a long-lived side token or read refresh secrets. An OAuth provider may not offer API keys at all.

For secure browser entry, a loopback-only one-time local form can receive the key and save it directly to the manager. It must restrict binding to loopback, use an anti-CSRF token and same-origin checks, avoid analytics/body logging, show masked inputs, stop after save, and never echo the value. Review the actual implementation before use. Clipboard/display handling depends on harness support; do not improvise raw-value transport through tool arguments.

No credential manager is installed by this skill's installer. Example profiles must be adapted to the actual business. Record whether the manager/gateway can renew automatically; do not promise static-key refresh. Preserve valid access until the replacement is validated and retirement is approved. Failed API checks never authorize plugin-token reuse.
